- **结论性质**：工程评估，不是完整渗透测试、真实摄像头压测或模型精度验收。

## 1. 总体结论

项目已经形成较完整的单机机器视觉闭环：**摄像头 → 多模型推理 → 规则判断 → 截图/告警 → 人工复核 → 数据集/标注 → 训练/模型注册**。统一 SQLite、配置版本检查、模型路由、故障与空检测结果区分等设计值得保留。

目前最主要的不足不是功能页面不够，而是：

1. **高权限入口的安全边界不足**：上传模型直接反序列化、训练注册路径未限制、默认管理员凭据与长期固定会话。
2. **离线工具会干扰在线检测**：测试/预标注修改共享模型阈值，默认阈值无法正确恢复；跨模型类别没有映射到数据集类别。
3. **时间状态不完整**：告警冷却跳过状态更新，连续滞留可能被错误延续；热更新的配置、运行状态和静态资源挂载并非统一发布。
4. **训练、备份与部署尚未形成可靠闭环**：训练结果不在持久化卷内，任务状态只在内存中，恢复缺少全量预检和停机互斥。
5. **验证与可观测性滞后于功能复杂度**：已有测试有效，但尚未进入 CI 发布门禁，关键并发和异常链路缺少测试。

**建议定位**：继续采用模块化单体和 SQLite，先解决安全、告警正确性和数据持久性，再根据测量结果做性能优化。不要把第一阶段变成微服务重写、替换数据库或全面换 UI 框架。

> **上线判断**：现有结果不能支持“可直接公开暴露管理端并接收不可信模型”的结论。受控内网试点也应先完成 P0/P1 中与自身使用场景相关的整改，并完成代表性视频验证。

## 5. 安全边界

### A01｜不可信模型与应用同进程加载（条件性 P0）

**证据**：[`webapp/state.py:683–748`](/Users/song/work/Machine/webapp/state.py#L683) 仅检查扩展名、长度、清洗文件名，然后在线程中执行 `YOLO(str(path))`；[`core/detector.py:80–95`](/Users/song/work/Machine/core/detector.py#L80) 也直接加载模型。线程不是安全隔离边界。

本机安装的 `ultralytics==8.4.123` 源码显示：`utils/__init__.py:72` 的 `ULTRALYTICS_SAFE_LOAD` 默认未启用；`nn/tasks.py:1742–1792` 默认走普通加载；`utils/patches.py:160–181` 在未指定参数时设置 `weights_only=False`。因此**不能因为使用较新 PyTorch 就假设应用的 checkpoint 加载受限**。本次没有制作或执行恶意模型，结论来自实际加载链路检查。

**风险条件**：攻击者需要有模型上传权限/有效面板凭据，或管理员导入了不可信权重；不是已证实的匿名执行漏洞。默认账号密码均为 `admin`、监听 `0.0.0.0`，Compose 未限定宿主机回环地址，且 Dockerfile 没有非 root `USER`，扩大了默认部署风险。

**优化**：
- 默认凭据改为首次启动一次性设置，未完成初始化不得开启敏感写入口；管理面仅供明确允许的网络访问。
- 明确模型来源与信任策略，记录文件 SHA-256、上传者及审批状态。
- 在隔离的低权限工作进程/容器验证权重，限制网络、文件系统、CPU/内存与运行时间；生产推理只加载通过审批的产物。
- 针对锁定版本评估受限加载模式兼容性，禁止失败后自动回退到不受限模式；受限加载不是完整沙箱的替代品。
- 非 root 运行、最小写目录、减少容器 capabilities；避免训练/校验进程获取面板密钥和数据库写权限。

**验收**：默认口令不能登录生产实例；未知来源权重进入隔离流程；校验超时/OOM/失败不影响面板与在线检测；拒绝的模型不会被实时加载。

### A02｜训练注册路径越界（P1，已复现）

**证据**：[`webapp/train_service.py:162–173`](/Users/song/work/Machine/webapp/train_service.py#L162)，[`webapp/api/train_api.py:42–48`](/Users/song/work/Machine/webapp/api/train_api.py#L42)。`register_best()` 直接拼接 `name` 和 `model_name`，先 `write_bytes()`，再调用 `register_model()`。`start()` 的任务名检查没有覆盖该独立注册入口。

**影响**：有权限调用 API 的用户能够跳出训练根目录选择源文件，或在模型目录外写入/覆盖以 `.pt` 结尾的目标文件；实际影响受进程文件权限和源 `weights/best.pt` 是否存在限制。即使后续注册拒绝非法名字，前面的文件副作用仍然存在。

**优化**：请求模型先校验 run/model 名称；解析后验证 `resolve().is_relative_to(root.resolve())`（包含符号链接逃逸）；拒绝绝对路径、分隔符、`.`/`..`；校验完整后才写临时文件并发布。用任务 ID 关联数据库产物，不直接接受自由路径；明确重名策略，失败时回滚文件。

**验收**：越界、绝对路径、符号链接、重复名均无越界读写、无残留文件；合法注册完整成功。

### A03｜会话生命周期与密码轮换（P1）

**证据**：[`utils/passwords.py:61–65`](/Users/song/work/Machine/utils/passwords.py#L61)、[`webapp/server.py:108–164`](/Users/song/work/Machine/webapp/server.py#L108)。token 仅由用户名和密码哈希确定；Cookie 的 7 天是客户端寿命，服务端没有签发/到期时间或撤销表。认证配置在创建 App 时被闭包捕获。Cookie 有 HttpOnly、SameSite=Lax，但没有 Secure；未发现登录节流和注销撤销接口。

**影响**：同一账号所有登录共享 token，不能单独撤销；手工重放固定 token 不受服务端期限约束。修改密码后旧认证持续生效直至重启。注意：设置 schema 已标记面板配置需重启，这是现有设计限制，不是“UI 已承诺立即换密但未实现”的证据。

**优化**：随机会话 ID + 服务端仅存摘要、绝对/空闲过期、注销撤销、换密立即撤销；HTTPS 部署下启用 Secure；登录失败节流和审计；敏感变更重新认证。若跨域/反向代理部署，明确 Origin/CSRF 策略，不依赖 SameSite 作为所有请求的唯一保护。

**验收**：独立登录生成不同 token；过期和撤销后重放失败；换密后旧密码及旧会话立即失效；不把 token、密码或完整 RTSP 凭据写入日志。

### B02｜预标注类别错配（P1，已复现）

**证据**：[`webapp/dataset_service.py:594–605`](/Users/song/work/Machine/webapp/dataset_service.py#L594)、[`webapp/dataset_service.py:635–653`](/Users/song/work/Machine/webapp/dataset_service.py#L635)。`_dets_to_yolo()` 直接把 `Detection.class_id` 写入标签，没有根据目标数据集 `names` 映射；保存标签仅过滤越界 ID，无法发现范围内的语义错误。

**影响**：模型与数据集的类别顺序不同就能静默生成错误标签，多模型各自 id=0 时尤其危险。若类别 ID 恰好越界，则有效检测可能被静默丢弃，最终影响训练数据质量。

**优化**：建立 `(model_version, class_id) → dataset_class_id` 映射；默认按规范化名称精确匹配，不做无提示模糊匹配；缺失/歧义映射须确认，未映射类别记为跳过而非错误标签。任务启动时冻结类别版本；保存来源模型、阈值、映射版本和人工审核状态。

**验收**：相同名称但顺序相反、多模型 ID 重叠、未知类别、类别热编辑等测试全部通过；预标注前可预览映射和跳过数量。

### B03｜连续滞留与冷却相互干扰（P1，已复现）

**证据**：[`main.py:401–405`](/Users/song/work/Machine/main.py#L401) 全部冷却时跳过推理；[`core/analyzer.py:358–372`](/Users/song/work/Machine/core/analyzer.py#L358) 单规则冷却时跳过 `check()`；[`core/analyzer.py:204–249`](/Users/song/work/Machine/core/analyzer.py#L204) 的 dwell 计时只有规则执行且看到中断才清理；图规则 [`core/rules_graph.py:495–506`](/Users/song/work/Machine/core/rules_graph.py#L495) 也有持续状态。

**影响**：冷却期看不到离开/重新出现，旧计时被错误沿用。断流、推理失败、停用/改区后的状态重置也缺少统一生命周期。区域滞留当前按类别而非 track ID 计时，是代码明确选择：若业务要求“同一个人停留 N 秒”，不能直接宣称满足该语义。

**优化**：拆开“状态推进”与“告警发送节流”；时序规则在冷却期继续更新状态，或在跳过观测时将连续性标为未知并按策略重置。设最大观测间隔、按规则版本重置、删除时释放状态。业务确需单个目标停留时再引入跟踪，不为所有规则盲目增加跟踪成本。

**验收**：离开后重入重新计时；断流恢复不继承不可证明的连续性；规则改区/停用再启用不继承旧时间；若要求个体滞留，A 离开 B 进入不能合并计时。

### B04｜配置提交不等于运行时应用成功（P2）

**验收**：内嵌/独立面板对同一字段效果一致；故意注入监听失败时，API/状态明确说明“已保存，应用失败”，不能虚报全部生效；快速连续修改不会旧版本覆盖新版本。

## 7. 数据可靠性、资源与部署

### C01｜训练产物和任务生命周期（P1）

**证据**：[`webapp/train_service.py:60–82`](/Users/song/work/Machine/webapp/train_service.py#L60) 使用 `PROJECT_ROOT/runs/panel`，而 [`docker-compose.yml:14–15`](/Users/song/work/Machine/docker-compose.yml#L14) 只挂载 `/app/storage`。`_proc/_meta` 只存在内存；[`main.py:497–517`](/Users/song/work/Machine/main.py#L497) 关闭时未调用 trainer.stop；worker 使用固定 name、`exist_ok=True`。

**优化**：统一到 `storage/runs/<job_id>`，迁移旧目录并纳入备份；数据库保存任务状态/配置/产物摘要；启动时把未完成任务标记 interrupted 并处理遗留进程。关闭时终止进程组并等待回收；设置训练资源配额/时段，禁止训练拖垮实时检测。冻结数据集/标签版本，避免训练中直接修改数据。

**验收**：容器重建后运行记录和产物保留；应用退出无遗留训练；同名请求获得不同 ID；训练中修改原数据集不改变该任务输入；训练并行时实时检测指标不越过约定阈值。

### C02｜备份“数据库一致”不等于整套恢复一致（P1）

**证据**：[`tools/backup_machine.py:35–55,75–98`](/Users/song/work/Machine/tools/backup_machine.py#L35) 先 copy 文件，再对**源文件**计算哈希；SQLite 备份之后的配置导出与文件复制仍读取活动数据。支持 `--project-root`，但 models/datasets 的根路径使用模块常量，需要统一解析。

[`tools/restore_machine.py:67–93`](/Users/song/work/Machine/tools/restore_machine.py#L67) 先替换数据库，再检查/复制 manifest 文件；未校验声明的 SHA-256，缺文件时跳过；[`infrastructure/persistence/machine_database.py:410–440`](/Users/song/work/Machine/infrastructure/persistence/machine_database.py#L410) 不获取主服务实例锁。README 恢复命令未明确要求停止所有数据库写入者。

**影响**：备份期间源文件变化会使 manifest 与备份内容不符；损坏/缺失文件可能在数据库替换后才暴露；恢复中途失败形成半恢复状态。活动 SQLite 连接/WAL 与文件替换的具体后果依环境而异，本次没有对真实数据库做破坏性实验。

**优化**：以备份数据库导出配置，计算目标文件哈希；对外部文件使用不可变版本或短暂停写/快照策略。恢复先完整验证格式版本、路径、来源链接边界、文件存在性、哈希和空间，再进入维护锁；在 staging 恢复并校验整套数据，发布失败能回滚。停掉所有写进程，包括独立面板；凭据备份另做权限/加密控制。

**验收**：缺失、篡改、越界 manifest 一律在修改目标前拒绝；运行中恢复被拒绝；异常注入后仍保留原可用数据集；空目录全量恢复演练可启动检测并访问截图。

### C03｜阻塞事件循环与上传资源限制（P1）

**证据**：[`webapp/api/detect_api.py:29–45`](/Users/song/work/Machine/webapp/api/detect_api.py#L29) 的 `async def` 内直接图像解码和同步推理；[`webapp/api/models_api.py:20–25`](/Users/song/work/Machine/webapp/api/models_api.py#L20) 先全量 `read()`，后由服务检查 200 MB；[`webapp/api/datasets_api.py:53–62`](/Users/song/work/Machine/webapp/api/datasets_api.py#L53) 将多文件全部读取到列表。登录路由还直接执行 CPU 密码哈希验证。

**验收**：并行上传/推理时轻量 API 仍满足延迟目标；超限请求在读完整个文件前拒绝；解码失败清理临时文件；队列有硬上限，内存用量不随请求数无限增长。
